# С чего начинать

## 1. Структура — уже разложена

```
pediatr-site/
├── CLAUDE.md
├── docs/
│   ├── design-system.md
│   └── sections.md
├── reference/
│   └── index.html          ← готовый визуальный эталон
├── src/content/
│   └── doctor.yaml
└── scripts/
    └── shot.mjs
```

Пути в `CLAUDE.md` сходятся, `.gitignore` на месте. Astro ещё не установлен —
это и есть содержание следующего шага.

## 2. Промпт на каркас

```
Прочитай CLAUDE.md, docs/design-system.md, docs/sections.md и reference/index.html.

reference/index.html — готовый одностраничник, собранный вручную. Он визуальный
эталон: дизайн переносим, а не переизобретаем.

Задача этого шага — только каркас, без секций:

1. Инициализируй Astro со статическим выводом, Tailwind, TypeScript strict,
   @astrojs/sitemap. Версии Astro и Tailwind проверь на месте, не по памяти:
   в Tailwind v4 нет tailwind.config.js и не нужен @astrojs/tailwind —
   там @tailwindcss/vite и токены через @theme прямо в CSS. Сначала посмотри,
   что реально встало, потом настраивай.
2. Перенеси палитру и типографику из docs/design-system.md в токены — способом,
   который подходит установленной версии Tailwind. Токен crimson-ink не забудь:
   он существует именно потому, что crimson не проходит AA на светлом.
   Шрифты — через @fontsource, самохостинг. CDN-подключение из эталона
   не переносить, оно там помечено комментарием.
3. Собери BaseLayout: html lang="ru", <main>, skip-link, мета и Open Graph
   из seo.*, футер с юридическим блоком из legal.*. Ни одной строки текста
   в компоненте — включая <title> и description.
4. Content Collections под src/content/doctor.yaml. Файл — один объект с семью
   разнородными ключами, а не массив однотипных записей, поэтому лоадер file()
   в лоб даст семь записей с несовместимыми схемами. Заведи отдельную коллекцию
   на каждый ключ через file(path, { parser }), схемы — zod.
   Единый файл сохраняем: он одновременно опросник для встречи с врачом.
5. Компонент <Ph> для плейсхолдеров. Две формы, обе обязательны:
     "PH::текст"          — плейсхолдер всё значение, префикс не рендерится
     "стаж {{00}} лет"    — плейсхолдер только внутри скобок
   Если строка начинается с PH::, скобки внутри не разбираются. Отмеченное
   получает класс .ph. Напиши на разбор пару тестов, это единственная логика
   во всём проекте.
6. Мета и разметка для поиска по docs/sections.md п. 11: canonical, Open Graph,
   JSON-LD Physician, robots.txt, 404. Поля с плейсхолдерами в JSON-LD
   не попадают вообще — лучше отсутствующее поле, чем "PH::" в выдаче.
   seo.site_url пока плейсхолдер: подставь заглушку в astro.config и оставь
   явный TODO, иначе sitemap соберётся с фиктивным доменом молча.
7. Добавь npm-скрипты dev / build / check / shot, поставь playwright.
8. Пустая главная, которая тянет данные из коллекций и рендерит только
   шапку, main и футер.

Секции не делай — они идут отдельными задачами. Покажи план перед началом.
```

## 3. Дальше

Одна секция — одна задача — один коммит, `/clear` между ними:

```
Собери секцию «Форматы приёма» по docs/sections.md, п. 3.
Эталон — блок .formats в reference/index.html. Данные из services[].
После сборки: npm run shot -- formats, посмотри PNG и раскритикуй результат.
```

Порядок: hero → форматы → о враче → темы → ход приёма → принципы →
разборы → контакты.

Id секций проставлены в эталоне и продублированы в `docs/sections.md`:
`hero`, `formats`, `about`, `topics`, `steps`, `myths`, `blog`, `contacts`.
Без id `npm run shot -- <секция>` не работает.

## Что решено и не пересматривается

- Форм на сайте нет. Персональных данных не собираем, поэтому 152-ФЗ и
  российский хостинг пока не нужны. Появится форма — переезжаем.
- WhatsApp не используем: заблокирован в РФ с февраля 2026. Telegram —
  с оговоркой. Основной канал — ВКонтакте.
- Instagram не встраиваем.
- MCP не подключаем: на статике браузерный сервер заменяет scripts/shot.mjs.
- Полноценный SDD не разводим. Спека — только docs/sections.md.
  Настоящая спека понадобится на этапе формы записи.
- Опорный вьюпорт — 360×640. Он жёстче iPhone SE и по ширине, и по высоте,
  поэтому проверяем на нём одном.
- Плейсхолдеры — две формы, `PH::` и `{{}}`, описаны в CLAUDE.md, п. 2.
  Третьей не заводим.
- **Лицензия у самого врача**, частный кабинет. Отсюда следует страница
  «Сведения об исполнителе» — см. docs/sections.md. Это отдельная строка в КП,
  а не мелочь в футере.

## Открытые вопросы к врачу

Все они уже стоят плейсхолдерами в doctor.yaml — пройди файл сверху вниз,
это и есть список для встречи. Отдельно, чего в файле нет:

- Регион приёма. Ник @pediatr_39 указывает на Калининградскую область —
  подтвердить, от этого зависит вся SEO-стратегия.
- Есть ли доступ к архиву постов для переноса в раздел «Разборы».
- Есть ли письменные согласия родителей на фото детей из постов.
- Готова ли к покупке шрифта Druk Cyrillic — он даст точное попадание
  в оформление ленты, Oswald это только замена.
- Есть ли домен. Без него canonical и sitemap собираются вхолостую.

## Решить до встречи, своими силами

- **Ставим ли счётчик аналитики.** Если да — появляется обработка ПД, а с ней
  политика и уведомление в РКН. Ссылка на политику в футере стоит видимым
  плейсхолдером до этого решения.
- **Состав страницы «Сведения об исполнителе»** — показать юристу, не
  додумывать самим.
